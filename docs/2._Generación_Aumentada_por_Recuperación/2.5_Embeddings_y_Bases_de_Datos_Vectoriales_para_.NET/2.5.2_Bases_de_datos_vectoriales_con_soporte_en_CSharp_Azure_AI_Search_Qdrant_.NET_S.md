# 2.5.2 Bases de datos vectoriales con soporte en C# (*Azure AI Search, Qdrant .NET SDK, Milvus, y PostgreSQL pgvector vía Entity Framework Core*)

Para que el pipeline de RAG sea efectivo, no basta con generar embeddings (vistos en el apartado 2.5.1); necesitamos un sistema capaz de almacenar estos vectores de alta dimensionalidad y realizar búsquedas de similitud de manera eficiente. En el ecosistema .NET, contamos con diversas opciones que van desde servicios administrados en la nube hasta soluciones locales y extensiones sobre bases de datos relacionales.

A continuación, analizamos las bases de datos vectoriales con mejor soporte para C# y cómo integrarlas.

---

### 2.5.2 Bases de datos vectoriales con soporte en C#

A diferencia de las bases de datos tradicionales que indexan texto o números de forma exacta, las bases de datos vectoriales utilizan algoritmos como **HNSW** (Hierarchical Navigable Small World) o **IVF** (Inverted File Index) para encontrar los vectores más cercanos a una consulta en un espacio multidimensional.

#### 1. Azure AI Search (Anteriormente Azure Cognitive Search)
Es la solución empresarial de Microsoft dentro de Azure. Es una plataforma de búsqueda de información (IR) que ha evolucionado para ser una base de datos vectorial de alto rendimiento.

*   **Ventajas:** Integración nativa con el SDK de Azure para .NET, soporte para búsqueda híbrida (vectorial + semántica + keyword) y escalabilidad automática.
*   **SDK:** `Azure.Search.Documents`

**Ejemplo de definición de índice en C#:**
```csharp
using Azure.Search.Documents.Indexes;
using Azure.Search.Documents.Indexes.Models;

public class HotelDoc
{
    [SimpleField(IsKey = true, IsFilterable = true)]
    public string Id { get; set; }

    [SearchableField]
    public string Description { get; set; }

    // Definición del campo vectorial (p. ej. 1536 dimensiones para OpenAI)
    [VectorSearchField(VectorSearchDimensions = 1536, VectorSearchProfileName = "my-vector-config")]
    public ReadOnlyMemory<float> DescriptionVector { get; set; }
}
```

#### 2. Qdrant
Qdrant es una base de datos vectorial de código abierto escrita en Rust, diseñada específicamente para manejar embeddings a gran escala. Destaca por su robusto SDK oficial para .NET.

*   **Ventajas:** Extremadamente rápida, permite filtrado por metadatos (payload) y ofrece una versión administrada o auto-alojada vía Docker.
*   **SDK:** `Qdrant.Client`

**Ejemplo de inserción de puntos en C#:**
```csharp
using Qdrant.Client;
using Qdrant.Client.Grpc;

var client = new QdrantClient("localhost", 6334);

await client.UpsertAsync("my_collection", new List<PointStruct>
{
    new PointStruct
    {
        Id = (ulong)Guid.NewGuid().GetHashCode(),
        Vectors = new float[] { 0.05f, 0.61f, 0.76f, ... }, // El embedding
        Payload = { { "filename", "manual_tecnico.pdf" } }
    }
});
```

#### 3. Milvus
Milvus es una base de datos vectorial graduada por la LF AI & Data Foundation, optimizada para aplicaciones de IA "cloud-native". Es ideal para sistemas que manejan miles de millones de vectores.

*   **Ventajas:** Arquitectura distribuida, separación de cómputo y almacenamiento, y soporte para múltiples índices vectoriales.
*   **SDK:** `Milvus.Client` (disponible en NuGet).

La integración con .NET es muy fluida mediante el uso de objetos fuertemente tipados para definir las colecciones y realizar búsquedas de similitud (Top-K).

#### 4. PostgreSQL con pgvector (vía Entity Framework Core)
Para muchos desarrolladores de .NET, la opción más natural es extender su base de datos relacional existente. La extensión `pgvector` permite a PostgreSQL almacenar y consultar vectores.

*   **Ventajas:** Permite realizar consultas que combinan datos relacionales (SQL) y vectoriales en una sola sentencia. Ideal para mantener la consistencia de datos sin añadir infraestructura nueva.
*   **Librería:** `Pgvector.EntityFrameworkCore`

**Configuración en el `DbContext`:**
```csharp
public class AppDbContext : DbContext
{
    public DbSet<DocumentChunk> Chunks { get; set; }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.HasPostgresExtension("vector");
        
        modelBuilder.Entity<DocumentChunk>()
            .Property(b => b.Embedding)
            .HasColumnType("vector(1536)"); // Tamaño del vector
    }
}

// Búsqueda de similitud de coseno en LINQ
var nearestChunks = await context.Chunks
    .OrderBy(c => c.Embedding.L2Distance(queryVector))
    .Take(5)
    .ToListAsync();
```

### Criterios de Selección para Proyectos .NET

Al elegir una base de datos vectorial para un pipeline RAG, se deben considerar los siguientes factores técnicos:

1.  **Ecosistema de Microsoft:** Si la aplicación ya reside en Azure y utiliza `Semantic Kernel`, **Azure AI Search** es la opción por defecto debido a su integración inmediata con los conectores de memoria del kernel.
2.  **Coste y Control:** Para proyectos que requieren despliegue *on-premise* o control total sobre la infraestructura sin los costes de servicios administrados, **Qdrant** o **Milvus** en contenedores Docker son las opciones más sólidas.
3.  **Simplicidad Arquitectónica:** Si el sistema ya utiliza **PostgreSQL**, añadir `pgvector` evita la complejidad de gestionar un "silo de datos" adicional y permite usar Entity Framework Core, manteniendo la lógica de negocio unificada.
4.  **Rendimiento en Búsqueda:** Para aplicaciones donde la latencia de recuperación es crítica y el volumen de documentos PDF es masivo (millones de fragmentos), las bases de datos vectoriales nativas (Qdrant/Milvus) suelen superar a las extensiones SQL en términos de *throughput*.
