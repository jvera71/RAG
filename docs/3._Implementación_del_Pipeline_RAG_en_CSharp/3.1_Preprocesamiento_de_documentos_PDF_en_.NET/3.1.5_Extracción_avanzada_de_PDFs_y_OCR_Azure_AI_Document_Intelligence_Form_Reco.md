# 3.1.5 Extracción avanzada de PDFs y OCR (*Azure AI Document Intelligence / Form Recognizer, Tesseract.NET*)

En el contexto de un pipeline de RAG, la calidad de la respuesta del LLM depende directamente de la calidad del texto extraído. Mientras que las librerías mencionadas en puntos anteriores (como `PdfPig` o `iText7`) son excelentes para extraer texto de capas digitales, fallan ante documentos escaneados o con estructuras complejas (tablas anidadas, columnas múltiples o formularios). Aquí es donde entran en juego las técnicas de **Extracción Avanzada y OCR**.

### 3.1.5 Extracción avanzada de PDFs y OCR

Cuando nos enfrentamos a PDFs "no estructurados" o "planos" (imágenes), el proceso de extracción requiere de un motor de Reconocimiento Óptico de Caracteres (OCR) que no solo identifique letras, sino que entienda la disposición espacial del contenido.

#### 1. Azure AI Document Intelligence (Anteriormente Form Recognizer)

Es la solución líder de Microsoft en la nube para el análisis de documentos. A diferencia de un OCR tradicional que solo devuelve una "bolsa de palabras", Azure AI Document Intelligence utiliza modelos de aprendizaje profundo para extraer texto, tablas, marcas de selección y estructuras de documentos.

**Ventajas para RAG:**
*   **Análisis de Layout:** Mantiene el orden de lectura lógico, lo cual es crítico para que el fragmentado (*chunking*) posterior no pierda el sentido semántico.
*   **Extracción de tablas:** Convierte tablas complejas a formatos estructurados (como Markdown o JSON), facilitando que el LLM comprenda las relaciones de datos.

**Implementación en C#:**

Para utilizarlo, se requiere el paquete NuGet `Azure.AI.FormRecognizer`. A continuación, un ejemplo de cómo utilizar el modelo de **Layout** para extraer contenido preservando la estructura:

```csharp
using Azure;
using Azure.AI.FormRecognizer.DocumentAnalysis;

// Configuración del cliente
string endpoint = "https://<tu-recurso>.cognitiveservices.azure.com/";
string apiKey = "TU_API_KEY";
var client = new DocumentAnalysisClient(new Uri(endpoint), new AzureKeyCredential(apiKey));

// Cargamos el PDF (puede ser un Stream o una URL)
using var stream = File.OpenRead("documento_complejo.pdf");

// Iniciamos el análisis con el modelo "prebuilt-layout"
AnalyzeDocumentOperation operation = await client.AnalyzeDocumentAsync(WaitUntil.Completed, "prebuilt-layout", stream);
AnalyzeResult result = operation.Value;

// Extracción de párrafos (ideal para el pipeline de RAG)
foreach (var paragraph in result.Paragraphs)
{
    Console.WriteLine($"Rol: {paragraph.Role} - Texto: {paragraph.Content}");
}

// Extracción de tablas estructuradas
foreach (var table in result.Tables)
{
    Console.WriteLine($"Tabla encontrada: {table.RowCount} filas, {table.ColumnCount} columnas");
    // Aquí podríamos convertir la tabla a Markdown para una mejor ingesta en el LLM
}
```

#### 2. Tesseract.NET

Para escenarios donde la privacidad de los datos impide el uso de la nube o se busca reducir costes operativos, **Tesseract** es el motor de OCR de código abierto más popular. En .NET, solemos utilizar el *wrapper* `Tesseract.NET` (de Charles Weld).

**Consideraciones técnicas:**
*   **Preprocesamiento:** Tesseract funciona mejor con imágenes. Para procesar PDFs, a menudo necesitamos una librería intermedia (como `Magick.NET` o `Ghostscript`) que convierta las páginas del PDF a imágenes de alta resolución (300 DPI).
*   **Archivos de idioma:** Requiere descargar archivos `.traineddata` para cada idioma que se desee procesar.

**Implementación en C#:**

Primero, instalamos el paquete NuGet `Tesseract`.

```csharp
using Tesseract;

// Nota: Tesseract procesa imágenes, no PDFs directamente. 
// Asumimos que la página del PDF ya ha sido convertida a un archivo de imagen.
public string PerformOcr(string imagePath)
{
    // El "testdata" es la carpeta que contiene los modelos de idioma (spa.traineddata)
    using var engine = new TesseractEngine(@"./tessdata", "spa", EngineMode.Default);
    using var img = Pix.LoadFromFile(imagePath);
    using var page = engine.Process(img);

    // Obtenemos el texto y el nivel de confianza
    string text = page.GetText();
    float confidence = page.GetMeanConfidence();

    return text;
}
```

#### Comparativa y Criterios de Selección

Para decidir qué herramienta integrar en el pipeline de RAG, evaluamos los siguientes puntos:

| Característica | Azure AI Document Intelligence | Tesseract.NET |
| :--- | :--- | :--- |
| **Costo** | Pago por uso (Cloud) | Gratuito (Open Source) |
| **Precisión** | Muy alta (especialmente en tablas y manuscritos) | Media (depende mucho de la calidad de la imagen) |
| **Facilidad** | Alta (API gestionada) | Compleja (gestión de dependencias nativas y preprocesamiento) |
| **Privacidad** | Datos procesados en Azure (requiere cumplimiento) | Procesamiento local (On-premise) |
| **Estructura** | Devuelve jerarquía, roles y tablas | Devuelve texto plano (string) |

#### Impacto en el flujo de RAG

La elección entre una extracción simple o una avanzada mediante OCR determinará el éxito de las fases posteriores del curso. Por ejemplo:
*   Si el PDF contiene una tabla con precios y usamos una extracción básica, los números se mezclarán como texto plano perdiendo su relación de fila/columna.
*   Al usar **Azure Document Intelligence**, podemos reconstruir esa tabla en formato Markdown dentro de nuestro `Chunk`, permitiendo que en el paso **3.3 (Generación)**, el LLM responda con precisión a preguntas como: *"¿Cuál es el precio del producto X según la tabla de la página 5?"*.

Este paso de extracción avanzada es el "filtro de entrada" que garantiza que el sistema de recuperación no esté indexando "basura" o texto incoherente proveniente de documentos mal digitalizados.
