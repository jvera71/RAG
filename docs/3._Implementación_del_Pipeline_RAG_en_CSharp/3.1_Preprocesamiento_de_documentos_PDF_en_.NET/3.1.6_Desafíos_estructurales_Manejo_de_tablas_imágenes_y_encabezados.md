# 3.1.6 Desafíos estructurales: Manejo de tablas, imágenes y encabezados

El procesamiento de documentos PDF para sistemas RAG presenta retos significativos que van más allá de la simple extracción de cadenas de texto. Un PDF no es un documento estructurado como un HTML o un Word; es, en esencia, una serie de instrucciones de dibujo en un lienzo 2D. En esta sección, analizaremos cómo abordar los desafíos estructurales que pueden degradar la calidad de nuestra recuperación si no se gestionan correctamente.

### 1. El Ruido de Encabezados y Pies de Página

En un flujo RAG, la presencia de encabezados (*headers*) y pies de página (*footers*) en cada página del PDF introduce "ruido" semántico. Si extraemos el texto de forma bruta, estas líneas repetitivas se insertarán en medio de párrafos que fueron divididos por un salto de página, rompiendo la coherencia del contexto y afectando la generación de *embeddings*.

**Estrategia de mitigación en .NET:**
Una técnica común es el filtrado basado en coordenadas espaciales. Utilizando librerías como `UglyToad.PdfPig`, podemos identificar elementos que se encuentran fuera de los márgenes de contenido útil.

```csharp
using UglyToad.PdfPig;
using UglyToad.PdfPig.Content;

public string ExtractCleanText(string pdfPath)
{
    using var document = PdfDocument.Open(pdfPath);
    var sb = new StringBuilder();

    foreach (var page in document.GetPages())
    {
        // Definir umbrales (ejemplo: ignorar los 50 puntos superiores e inferiores)
        var topThreshold = page.Height - 50;
        var bottomThreshold = 50;

        var words = page.GetWords()
            .Where(w => w.BoundingBox.Bottom > bottomThreshold && w.BoundingBox.Top < topThreshold);

        foreach (var word in words)
        {
            sb.Append(word.Text + " ");
        }
        sb.AppendLine();
    }
    return sb.ToString();
}
```

### 2. Tablas: La Pérdida de Relaciones Lineales

Las tablas son el mayor desafío para la extracción de texto. Cuando un motor de extracción estándar lee una tabla, a menudo lo hace de izquierda a derecha, mezclando los datos de las celdas de diferentes columnas en una sola línea de texto sin sentido.

**El problema:** Una fila que dice "Producto A | $100 | En stock" se convierte en "Producto A $100 En stock". Multiplicado por cientos de filas, el LLM pierde la noción de qué valor pertenece a qué columna.

**Solución técnica:**
Para RAG, lo ideal es convertir las tablas a formato **Markdown** o **HTML**, ya que los LLMs comprenden excepcionalmente bien estas estructuras.
*   **Enfoque Heurístico:** Usar `Tabula-py` (vía proceso externo) o algoritmos de detección de columnas en C# analizando los espacios en blanco (`x-coordinates`) entre palabras.
*   **Enfoque Basado en Modelos:** Utilizar *Azure AI Document Intelligence*. Su SDK para .NET (`Azure.AI.FormRecognizer`) devuelve un objeto `Tables` que conserva la estructura de filas y columnas, permitiéndonos reconstruir la tabla como un bloque de texto semánticamente rico.

### 3. Imágenes y Gráficos (Contexto Visual)

Muchos PDFs contienen información crítica en diagramas de flujo, gráficos de barras o capturas de pantalla. El texto dentro de estas imágenes no es accesible mediante la extracción de texto estándar.

*   **Extracción de Metadatos y Alt-Text:** Rara vez los PDFs técnicos incluyen texto alternativo.
*   **OCR Integrado:** Si el PDF es una imagen escaneada, es obligatorio el uso de OCR (como Tesseract o Azure AI).
*   **Estrategia de "Captions":** Una técnica avanzada consiste en extraer la imagen, enviarla a un modelo multimodal (como GPT-4o) para generar una descripción textual y reinsertar esa descripción en el pipeline de texto en el lugar donde se encontraba la imagen.

### 4. Flujo de Lectura y Columnas Múltiples

Los artículos científicos y financieros suelen utilizar diseños de doble columna. Un extractor ingenuo leerá la primera línea de la columna A seguida de la primera línea de la columna B, resultando en un texto ininteligible.

**Implementación en C# con PdfPig:**
Debemos utilizar algoritmos de agrupación de texto (como *Nearest Neighbour*) que respeten la segmentación de bloques.

```csharp
using UglyToad.PdfPig.DocumentLayoutAnalysis.TextExtractor;
```

### 5. Resumen de Desafíos y Mejores Prácticas

| Elemento | Problema para RAG | Solución Recomendada |
| :--- | :--- | :--- |
| **Encabezados** | Fragmentan el contexto semántico. | Filtrado por coordenadas (Bounding Boxes). |
| **Tablas** | Lectura lineal errónea. | Conversión a Markdown/JSON (Azure Document Intelligence). |
| **Imágenes** | Información invisible para el LLM. | OCR o descripción multimodal (Image-to-Text). |
| **Columnas** | Mezcla de frases de distintos bloques. | Algoritmos de segmentación de layout (XY-Cut). |

Al abordar estos desafíos estructurales, aseguramos que los fragmentos (*chunks*) que alimentarán nuestra base de datos vectorial (tema que trataremos en la sección 3.2) sean representaciones fieles y coherentes del conocimiento contenido en el PDF, minimizando así las alucinaciones del modelo por falta de contexto estructurado.
