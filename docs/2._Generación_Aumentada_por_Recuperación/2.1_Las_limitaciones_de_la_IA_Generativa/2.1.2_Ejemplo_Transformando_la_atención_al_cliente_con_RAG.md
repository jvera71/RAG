# 2.1.2 Ejemplo: Transformando la atención al cliente con RAG

### 2.1.2 Ejemplo: Transformando la atención al cliente con RAG

Para comprender el valor real de RAG, consideremos el escenario de una empresa tecnológica ficticia llamada **"TechNova"**, que comercializa dispositivos domésticos inteligentes. TechNova tiene un catálogo de más de 100 productos, cada uno con manuales técnicos, guías de solución de problemas y políticas de garantía extensas en formato PDF.

#### El escenario sin RAG (Dependencia exclusiva del LLM)

Supongamos que un cliente consulta al chatbot de soporte: *"¿Cómo puedo resetear mi termostato TechNova modelo G2 si la pantalla está bloqueada?"*.

Si el chatbot utiliza un LLM estándar (como GPT-4) sin RAG:
1.  **Conocimiento desactualizado:** El modelo fue entrenado hace meses. El modelo G2 se lanzó hace apenas tres semanas. El LLM no sabe que existe.
2.  **Alucinación:** El modelo, programado para ser útil, intenta inferir una respuesta basada en termostatos similares. Sugiere "mantener presionado el botón de encendido por 10 segundos".
3.  **Consecuencia:** El modelo G2 no tiene botones físicos (es táctil). El cliente se frustra y la empresa pierde credibilidad.

#### La transformación mediante RAG

Al implementar RAG en el ecosistema .NET de TechNova, el proceso cambia radicalmente. El sistema ya no depende de lo que el LLM "recuerda", sino de lo que puede "leer" en los manuales oficiales en el momento de la consulta.

El flujo de trabajo transformado sería el siguiente:

1.  **Consulta:** El usuario hace la misma pregunta.
2.  **Recuperación (Retrieval):** El sistema busca en la base de datos de manuales PDF de TechNova los fragmentos más relevantes sobre "resetear", "bloqueada" y "G2".
3.  **Aumentación (Augmentation):** El sistema construye un nuevo prompt que incluye esos fragmentos técnicos específicos extraídos del PDF.
4.  **Generación:** El LLM redacta una respuesta basada *estrictamente* en el contexto proporcionado.

#### Implementación conceptual en C#

A continuación, se muestra cómo se vería la orquestación de este ejemplo utilizando un enfoque de servicios en .NET. En esta etapa del curso, nos enfocamos en la lógica de negocio; los detalles de los modelos de *embeddings* y las bases de datos vectoriales se profundizarán en las secciones 2.5 y 3.2.

```csharp
using System;
using System.Threading.Tasks;
using Microsoft.SemanticKernel; // Utilizando el ecosistema mencionado en 1.5

public class CustomerSupportService
{
    private readonly IKernel _kernel;
    private readonly IVectorStore _vectorDatabase; // Representación de nuestro sistema de recuperación

    public CustomerSupportService(IKernel kernel, IVectorStore vectorDatabase)
    {
        _kernel = kernel;
        _vectorDatabase = vectorDatabase;
    }

    public async Task<string> ProcessSupportQueryAsync(string userQuery)
    {
        // 1. Recuperar contexto relevante de los PDFs de TechNova
        // En lugar de confiar en el conocimiento interno del LLM, buscamos en los documentos
        var relevantContext = await _vectorDatabase.SearchRelevantManualsAsync(userQuery, limit: 3);

        // 2. Definir el System Prompt con el contexto inyectado
        // Esto mitiga alucinaciones al forzar al modelo a usar los fragmentos recuperados
        var promptTemplate = @"
            Eres un asistente técnico de TechNova. 
            Utiliza únicamente la siguiente información de los manuales para responder:
            
            [CONTEXTO]
            {{$context}}
            
            [PREGUNTA DEL CLIENTE]
            {{$query}}
            
            Si la información no está en el contexto, indica que no tienes esa información 
            específica y ofrece escalar el caso a un humano.";

        // 3. Ejecutar la generación aumentada
        var arguments = new KernelArguments
        {
            { "context", string.Join("\n", relevantContext) },
            { "query", userQuery }
        };

        var result = await _kernel.InvokePromptAsync(promptTemplate, arguments);

        return result.ToString();
    }
}
```

#### Beneficios inmediatos en la Atención al Cliente

1.  **Veracidad y Citación:** El sistema puede incluso indicar en qué página del manual del modelo G2 encontró la instrucción (gracias a los metadatos que veremos en la sección 3.2.3).
2.  **Reducción de Costes de Soporte:** Consultas técnicas complejas que antes requerían un agente humano de Nivel 2 ahora son resueltas por el sistema RAG con precisión quirúrgica.
3.  **Seguridad Operativa:** Al limitar la respuesta al contexto (Sección 2.1.1), evitamos que el bot de soporte hable de temas no relacionados o de la competencia.

Este ejemplo ilustra que RAG no es solo una mejora técnica, sino un cambio de paradigma: pasamos de una IA que "cree saberlo todo" a una IA que "sabe buscar y sintetizar la verdad organizacional".
