# 3.1.2 Manejo de múltiples páginas

En el desarrollo de un pipeline de RAG, tratar un PDF como un bloque de texto único y monolítico es un error común que degrada la calidad de la recuperación y la experiencia del usuario final. El **manejo de múltiples páginas** es el proceso de iterar, organizar y etiquetar el contenido de un documento respetando su estructura física original.

### La importancia de la segmentación por página

A diferencia de los archivos de texto plano, los PDFs están diseñados para la visualización, no para el procesamiento de datos. Al extraer contenido, debemos preservar la información de la página por tres razones fundamentales:

1.  **Trazabilidad y Citación:** Para que el sistema RAG sea confiable, el LLM debe ser capaz de indicar la fuente exacta (p. ej., *"Según la página 45 del manual..."*).
2.  **Gestión de Memoria:** Procesar documentos de cientos de páginas requiere un enfoque iterativo para evitar excepciones de `OutOfMemory`.
3.  **Contexto Espacial:** A menudo, los encabezados y pies de página se repiten en cada página y deben ser identificados o filtrados para no "ensuciar" los embeddings.

### Implementación técnica en C#

Utilizando la librería **PdfPig** (mencionada en el apartado 3.1.1), el enfoque recomendado es mapear cada página a un objeto de transferencia de datos (DTO) que preserve su metainformación antes de pasar a la fase de limpieza y fragmentación (*chunking*).

#### Ejemplo: Extracción estructurada por páginas

A continuación, se muestra cómo implementar un extractor que recorre el documento y encapsula el contenido de cada página:

```csharp
using System;
using System.Collections.Generic;
using UglyToad.PdfPig;
using UglyToad.PdfPig.Content;

public class DocumentPage
{
    public int PageNumber { get; set; }
    public string Content { get; set; }
    public string SourceName { get; set; }
}

public class PdfPageProcessor
{
    public IEnumerable<DocumentPage> ExtractPages(string filePath)
    {
        using (PdfDocument document = PdfDocument.Open(filePath))
        {
            foreach (Page page in document.GetPages())
            {
                // Extraer texto de la página actual
                string pageText = page.Text;

                // Es importante capturar el número de página (Base 1 en PdfPig)
                yield return new DocumentPage
                {
                    PageNumber = page.Number,
                    Content = pageText,
                    SourceName = System.IO.Path.GetFileName(filePath)
                };
            }
        }
    }
}
```

### Consideraciones sobre el flujo de datos

Al manejar múltiples páginas, debemos decidir cómo gestionar los límites entre ellas. En un pipeline RAG robusto, se deben considerar los siguientes aspectos técnicos:

#### 1. Preservación de metadatos para la base de datos vectorial
Cada fragmento de texto (*chunk*) generado posteriormente en la sección 3.2 heredará el número de página obtenido en este paso. Esto permite que, tras una búsqueda por similitud, el sistema recupere no solo el texto, sino el número de página exacto para generar una respuesta con referencias bibliográficas precisas.

#### 2. El problema de las palabras cortadas (Hyphenation)
Es frecuente que una palabra se divida al final de una página (p. ej., "comun- [salto de página] icación"). Un manejo básico de múltiples páginas simplemente concatenaría los textos, dejando "comun- icación" en el corpus. Durante la iteración por páginas, se recomienda implementar una lógica de unión que detecte guiones al final de la última línea de una página para reconstruir la palabra antes de enviar el contenido al siguiente paso del pipeline.

#### 3. Carga perezosa (Lazy Loading)
Para aplicaciones escalables en .NET, el uso de `IEnumerable<T>` con la palabra clave `yield return` (como se muestra en el ejemplo anterior) es crítico. Esto permite procesar una página a la vez sin necesidad de cargar todo el contenido del PDF en la RAM del servidor, lo cual es vital cuando se integran estos procesos en *Worker Services* o *Azure Functions*.

### Siguientes pasos en el Pipeline
Una vez que tenemos el contenido segmentado por páginas, el flujo natural es proceder a la **limpieza y normalización** (Sección 3.1.3), donde eliminaremos ruidos específicos de la paginación como números de página al pie, encabezados institucionales recurrentes y marcas de agua que, de persistir, diluirían la semántica de nuestros vectores en la base de datos.
