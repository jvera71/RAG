# 3.1.4 Detección de idioma

Dentro de la fase de preprocesamiento de documentos para un sistema RAG, la **detección de idioma** es un paso crítico que a menudo se pasa por alto. Una vez que hemos extraído el texto de un PDF (visto en la sección 3.1.1) y lo hemos normalizado (sección 3.1.3), determinar el idioma del contenido es fundamental para asegurar el éxito de las etapas posteriores del pipeline.

### ¿Por qué es crucial la detección de idioma en RAG?

La detección precisa del idioma influye directamente en tres áreas que se tratarán más adelante en este curso:

1.  **Selección del modelo de Embeddings (Sección 2.5.1):** No todos los modelos son multilingües. Si detectamos que el documento está en un idioma específico (ej. alemán), podríamos optar por un modelo especializado en ese idioma para obtener vectores con mayor semántica que los de un modelo genérico.
2.  **Estrategias de Chunking (Sección 3.2.2):** Las reglas de división de texto (tokenización) varían según el idioma. El manejo de stop-words y la segmentación de oraciones dependen de la gramática del idioma detectado.
3.  **Filtrado de Metadatos (Sección 3.2.3):** Almacenar el idioma como metadato en la base de datos vectorial permite realizar filtrados previos en la consulta, evitando que el sistema recupere fragmentos en idiomas que el usuario no solicitó o no comprende.

### Implementación en .NET

Para implementar la detección de idioma en C#, tenemos principalmente dos enfoques: el uso de servicios en la nube (máxima precisión y soporte de idiomas) o el uso de librerías locales basadas en ML (menor latencia y costo).

#### 1. Enfoque Cloud: Azure AI Language SDK
En entornos empresariales que ya utilizan el ecosistema de Azure, la opción más robusta es `Azure.AI.TextAnalytics`. Este servicio utiliza modelos de aprendizaje profundo avanzados para identificar idiomas incluso en textos cortos o ambiguos.

**Ejemplo de implementación:**

```csharp
using Azure;
using Azure.AI.TextAnalytics;

public class LanguageDetectorService
{
    private readonly TextAnalyticsClient _client;

    public LanguageDetectorService(string endpoint, string apiKey)
    {
        _client = new TextAnalyticsClient(new Uri(endpoint), new AzureKeyCredential(apiKey));
    }

    public async Task<string> DetectLanguageAsync(string text)
    {
        try
        {
            // Solo necesitamos una muestra del texto para detectar el idioma
            string sampleText = text.Length > 1000 ? text.Substring(0, 1000) : text;
            
            DetectedLanguage language = await _client.DetectLanguageAsync(sampleText);
            return language.Iso6391Name; // Retorna "es", "en", "fr", etc.
        }
        catch (RequestFailedException ex)
        {
            // Manejo de errores de API
            return "unknown";
        }
    }
}
```

#### 2. Enfoque Local: Librerías de Inferencia de ML
Si la privacidad de los datos es crítica o se requiere procesar miles de documentos sin incurrir en costos de API, podemos optar por librerías como `LanguageDetection` (basada en perfiles de n-gramas) o implementaciones de ONNX.

Una opción popular y ligera para .NET es el uso de ports de **CLD3 (Compact Language Detector 3)** o librerías basadas en perfiles estadísticos:

```csharp
using LanguageDetection; // Usando el paquete NuGet 'LanguageDetection'

public class LocalLanguageDetector
{
    private readonly LanguageDetector _detector;

    public LocalLanguageDetector()
    {
        _detector = new LanguageDetector();
        // Cargamos los perfiles de idiomas que queremos soportar
        _detector.AddAllLanguages(); 
    }

    public string Detect(string text)
    {
        // El motor analiza la distribución estadística de los caracteres
        string languageCode = _detector.Detect(text);
        return languageCode ?? "unknown";
    }
}
```

### Desafíos Técnicos: Documentos Multilingües

Un desafío común en el preprocesamiento de PDFs es encontrar documentos que contienen varios idiomas (por ejemplo, un manual técnico con secciones en inglés y español). 

*   **Detección por fragmentos:** En lugar de detectar el idioma de todo el documento al inicio, es una práctica recomendada realizar la detección tras la extracción de párrafos o páginas.
*   **Umbral de confianza:** Al utilizar servicios como Azure AI Language, el sistema devuelve un "score" de confianza (0 a 1). En el pipeline RAG, si la confianza es inferior a 0.8, se suele etiquetar el fragmento como `undefined` para evitar que un chunk mal clasificado contamine los resultados de búsqueda vectorial.

### Integración en el Pipeline RAG

La salida de este módulo debe inyectarse en el objeto de datos que fluye hacia el **Pipeline de Ingesta (Sección 3.2)**. Un registro típico de preprocesamiento se vería así en C#:

```csharp
public record ProcessedDocument(
    string Id,
    string RawText,
    string CleanedText,
    string LanguageCode, // Determinado en este paso
    Dictionary<string, string> Metadata
);
```

Con el `LanguageCode` ya identificado, el pipeline está listo para avanzar hacia la **Detección Avanzada y OCR (Sección 3.1.5)**, donde el idioma detectado puede ayudar a los motores de OCR a seleccionar el diccionario de reconocimiento de caracteres adecuado.
