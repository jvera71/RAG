# 5.2 Despliegue en producción: Creación de APIs RAG con *ASP.NET Core Minimal APIs*, *gRPC* o *Blazor*

Una vez que hemos construido y validado nuestro pipeline de RAG (desde la ingesta hasta la generación), el siguiente paso crítico es exponer esta funcionalidad a través de una interfaz robusta y escalable. En el ecosistema .NET, tenemos tres enfoques principales dependiendo de las necesidades de consumo de nuestra aplicación.

### 5.2.1 ASP.NET Core Minimal APIs: El estándar para Microservicios

Las Minimal APIs son la opción predilecta para exponer motores de RAG debido a su baja sobrecarga (overhead) y su sintaxis fluida. En un entorno de producción, es fundamental manejar las respuestas del LLM de forma eficiente, especialmente mediante el **streaming de tokens**.

#### Implementación de un Endpoint de Consulta (Query)
Para evitar que el usuario espere a que se genere la respuesta completa, utilizamos `IAsyncEnumerable<string>` para transmitir la respuesta conforme el modelo la genera.

```csharp
using Microsoft.AspNetCore.Mvc;
using Microsoft.SemanticKernel;
using Microsoft.SemanticKernel.ChatCompletion;

var builder = WebApplication.CreateBuilder(args);

// Registro de servicios (Previamente configurados en secciones 2 y 3)
builder.Services.AddScoped<IRagService, RagService>();
builder.Services.AddSingleton<IChatCompletionService>(sp => 
    new AzureOpenAIChatCompletionService("deployment", "endpoint", "api-key"));

var app = builder.Build();

app.MapPost("/api/rag/ask", async (
    [FromBody] QueryRequest request, 
    IRagService ragService,
    CancellationToken ct) =>
{
    // 1. Recuperación de contexto (Retrieval)
    var context = await ragService.GetContextAsync(request.Question, ct);

    // 2. Generación con streaming
    var stream = ragService.GetAnswerStreamingAsync(request.Question, context, ct);

    return Results.Ok(stream);
})
.WithName("AskRAG")
.WithOpenApi();

app.Run();

public record QueryRequest(string Question);
```

### 5.2.2 gRPC: Comunicación de Alto Rendimiento entre Servicios

Si nuestro sistema RAG forma parte de una arquitectura de microservicios interna (por ejemplo, un servicio de "Cerebro Central" consultado por otros servicios de la empresa), **gRPC** es superior a REST debido a su serialización binaria (Protobuf) y su soporte nativo para streaming bidireccional.

#### Definición del Contrato (.proto)
```proto
syntax = "proto3";

service RagEngine {
  rpc AskStream (RagRequest) returns (stream RagResponse);
}

message RagRequest {
  string query = 1;
  string document_filter = 2;
}

message RagResponse {
  string chunk = 1;
}
```

#### Implementación del Servicio en C#
```csharp
public class RagGrpcService : RagEngine.RagEngineBase
{
    private readonly IRagService _ragService;

    public RagGrpcService(IRagService ragService) => _ragService = ragService;

    public override async Task AskStream(
        RagRequest request, 
        IServerStreamWriter<RagResponse> responseStream, 
        ServerCallContext context)
    {
        var ragStream = _ragService.GetAnswerStreamingAsync(request.Query, null, context.CancellationToken);

        await foreach (var textChunk in ragStream)
        {
            await responseStream.WriteAsync(new RagResponse { Chunk = textChunk });
        }
    }
}
```

### 5.2.3 Blazor: Interfaces de Usuario Interactivas para RAG

Blazor (especialmente en su modalidad *Interactive Server*) permite crear paneles de administración de documentos y chats de IA sin salir de C#. Es ideal para herramientas internas donde los empleados interactúan con los PDFs cargados.

#### Componente de Chat con Streaming en Blazor
Al integrar RAG en Blazor, la clave es actualizar el estado de la UI en tiempo real mientras llegan los fragmentos de texto del LLM.

```razor
@page "/chat"
@inject IRagService RagService

<div class="chat-container">
    <input @bind="userQuery" placeholder="Pregunta sobre tus documentos..." />
    <button @onclick="HandleSubmit" disabled="@isProcessing">Enviar</button>

    <div class="response-area">
        <p>@currentResponse</p>
    </div>
</div>

@code {
    private string userQuery = "";
    private string currentResponse = "";
    private bool isProcessing = false;

    private async Task HandleSubmit()
    {
        isProcessing = true;
        currentResponse = "";
        
        // Obtenemos el flujo de datos del servicio RAG
        var stream = RagService.GetAnswerStreamingAsync(userQuery);

        await foreach (var chunk in stream)
        {
            currentResponse += chunk;
            StateHasChanged(); // Forzamos el renderizado de la UI con cada token
        }

        isProcessing = false;
    }
}
```

### 5.2.4 Consideraciones de Producción

Para que estas APIs sean viables en un entorno real, debemos implementar patrones que aseguren la resiliencia:

1.  **Throttling y Rate Limiting:** Las llamadas a LLMs (OpenAI, Anthropic) tienen límites de cuota y costos asociados. Usar el middleware de `Microsoft.AspNetCore.RateLimiting` es obligatorio.
2.  **Carga de Archivos Robusta:** Para la ingesta de PDFs vía API, se recomienda no procesar el archivo síncronamente en el endpoint `POST`. En su lugar, el endpoint debe guardar el archivo en un almacenamiento (Azure Blob Storage) y encolar un mensaje para un procesamiento asíncrono (tópico que se ampliará en la sección 5.4).
3.  **Manejo de Timeouts:** Los modelos de lenguaje pueden ser lentos. Es vital configurar correctamente los tiempos de espera tanto en el cliente como en el HttpClient interno que se comunica con el LLM.
4.  **CORS y Seguridad:** Al exponer Minimal APIs para ser consumidas por Front-ends externos, se debe configurar estrictamente la política de CORS y la autenticación mediante JWT o Entra ID (como se mencionó en la sección 2.8).
