# 3.3.2 Integración del modelo generativo (*Azure.AI.OpenAI SDK*)

Una vez que hemos estructurado nuestros prompts y definido la lógica de negocio para interactuar con el usuario, el siguiente paso crítico es la **integración técnica con el modelo generativo**. En el ecosistema .NET, la herramienta estándar y más robusta para esto es el SDK oficial `Azure.AI.OpenAI`.

Este componente actúa como el "cerebro" final del pipeline RAG. Su función es recibir el prompt (que ya contiene el contexto recuperado de la base de datos vectorial y la pregunta del usuario) y generar una respuesta coherente y fundamentada.

### Configuración del SDK de Azure OpenAI

Para comenzar, es necesario integrar el paquete NuGet:
`dotnet add package Azure.AI.OpenAI`

A diferencia de las llamadas REST directas, el SDK gestiona automáticamente aspectos complejos como la serialización de JSON, el manejo de reintentos (políticas de *retry*) y la autenticación segura.

### Implementación del Cliente de Generación

La pieza central es la clase `OpenAIClient`. En entornos empresariales (como se mencionó en el punto 2.8), se recomienda el uso de `DefaultAzureCredential` para una integración fluida con **Azure Entra ID**, evitando el manejo de claves de API en texto plano.

```csharp
using Azure;
using Azure.AI.OpenAI;
using Azure.Identity;

// Configuración del cliente
string endpoint = "https://tu-recurso.openai.azure.com/";
var client = new OpenAIClient(new Uri(endpoint), new DefaultAzureCredential());

// Nombre del despliegue (deployment name) del modelo en Azure AI Studio
string deploymentName = "gpt-4o"; 
```

### Ejecución de la Inferencia (Chat Completions)

En un flujo RAG, no solemos usar modelos de "Completion" simple, sino el modelo de **Chat Completions**. Este permite definir roles (System, User, Assistant), lo cual es fundamental para inyectar el contexto de los PDFs de manera que el modelo entienda que debe actuar como un asistente basado exclusivamente en la información proporcionada.

A continuación, se muestra cómo integrar el prompt estructurado (visto en el punto 3.3.1) con los resultados de la búsqueda vectorial:

```csharp
public async Task<string> GenerarRespuestaAsync(string query, string contextoRecuperado)
{
    var chatCompletionsOptions = new ChatCompletionsOptions()
    {
        DeploymentName = deploymentName,
        Messages =
        {
            // Mensaje de sistema: Define el comportamiento y contiene el contexto de los PDFs
            new ChatRequestSystemMessage("Eres un asistente técnico que responde preguntas basadas únicamente en los fragmentos de PDF proporcionados."),
            new ChatRequestSystemMessage($"Contexto relevante extraído de los documentos:\n{contextoRecuperado}"),
            
            // Mensaje de usuario: La pregunta real
            new ChatRequestUserMessage(query)
        },
        // Parámetros de control de generación
        Temperature = 0.1f, // Baja temperatura para reducir alucinaciones
        MaxTokens = 800,
        NucleusSamplingFactor = 0.95f
    };

    Response<ChatCompletions> response = await client.GetChatCompletionsAsync(chatCompletionsOptions);
    return response.Value.Choices[0].Message.Content;
}
```

### Consideraciones Técnicas Clave

1.  **Manejo de Tokens:** El SDK permite monitorear el uso de tokens a través de la propiedad `Usage` en la respuesta. Esto es vital para el control de costes y para evitar exceder el límite de la ventana de contexto del modelo (especialmente relevante cuando el `contextoRecuperado` es extenso).
2.  **Streaming de Respuestas:** Para mejorar la experiencia de usuario (UX), especialmente en aplicaciones web o bots, el SDK permite recibir la respuesta en tiempo real mediante *Server-Sent Events* (SSE). Esto se logra con el método `GetChatCompletionsStreamingAsync`, permitiendo que el texto aparezca palabra por palabra en la interfaz.
3.  **Seguridad y Filtrado de Contenido:** Al usar el SDK de Azure, las respuestas pasan automáticamente por los filtros de seguridad de Azure AI Content Safety. El SDK permite capturar excepciones si una respuesta es bloqueada debido a políticas de contenido sensible, un punto clave para la robustez en entornos corporativos.

Esta integración cierra el ciclo del pipeline básico: desde la extracción del PDF hasta la entrega de una respuesta generada. En la siguiente sección (3.4), abordaremos cómo evaluar si esta respuesta es realmente fiel al documento original.
