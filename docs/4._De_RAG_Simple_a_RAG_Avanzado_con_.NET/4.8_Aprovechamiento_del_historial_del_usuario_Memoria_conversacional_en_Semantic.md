# 4.8 Aprovechamiento del historial del usuario (*Memoria conversacional en Semantic Kernel / Bot Framework*)

En el desarrollo de sistemas RAG avanzados, uno de los mayores desafíos es la transición de una interacción estática (pregunta-respuesta única) a una experiencia conversacional fluida. Mientras que un sistema RAG básico trata cada consulta de forma aislada (stateless), el **aprovechamiento del historial del usuario** permite que el modelo comprenda referencias anafóricas ("¿Cuál es *su* salario?", donde "su" refiere a un sujeto mencionado anteriormente) y mantenga la coherencia a lo largo de una sesión.

### 4.8.1 El concepto de Memoria Conversacional en RAG

En el contexto de .NET y Semantic Kernel, la memoria conversacional no se refiere a la base de datos vectorial (memoria semántica), sino al registro cronológico de los intercambios entre el usuario y el asistente dentro de una sesión específica.

Para que un pipeline RAG sea verdaderamente efectivo con historial, se suele seguir un flujo de dos pasos:
1.  **Contextualización de la consulta:** El sistema toma la nueva pregunta del usuario y el historial reciente para generar una "pregunta independiente" (standalone question) que contenga toda la información necesaria para realizar la búsqueda vectorial.
2.  **Generación con Historial:** Una vez recuperados los fragmentos del PDF, se le entrega al LLM tanto el contexto recuperado como el historial de la conversación para redactar la respuesta final.

### 4.8.2 Gestión del historial con Semantic Kernel

Semantic Kernel facilita esta gestión mediante la clase `ChatHistory`. Esta clase actúa como un contenedor de mensajes con roles definidos (`User`, `Assistant`, `System`).

#### Ejemplo de implementación de `ChatHistory`

```csharp
using Microsoft.SemanticKernel;
using Microsoft.SemanticKernel.ChatCompletion;

// Inicialización del historial
var chatHistory = new ChatHistory("Eres un asistente experto que responde preguntas basadas en documentos técnicos.");

// Simulación de una interacción previa
chatHistory.AddUserMessage("¿Quién es el autor del manual de seguridad?");
chatHistory.AddAssistantMessage("El autor es el departamento de Ciberseguridad de ACME Corp.");

// Nueva consulta con referencia implícita
string currentQuery = "¿Cuándo se actualizó por última vez?";
chatHistory.AddUserMessage(currentQuery);

// El historial ahora contiene el contexto necesario para entender que "se" refiere al manual.
```

### 4.8.3 Estrategias de manejo de la ventana de contexto

A medida que la conversación progresa, el historial puede crecer hasta exceder el límite de tokens del modelo. En .NET, debemos implementar estrategias de poda o resumen:

1.  **Sliding Window (Ventana Deslizante):** Mantener solo los últimos *N* mensajes. Es sencillo de implementar en C# manipulando la lista de `ChatHistory`.
2.  **Summarization (Resumen):** Cuando el historial alcanza un umbral, se solicita al LLM que resuma la conversación hasta el momento, sustituyendo los mensajes antiguos por un único mensaje de sistema con el resumen.

```csharp
// Ejemplo de Sliding Window simple
if (chatHistory.Count > 10)
{
    // Removemos los mensajes más antiguos manteniendo el mensaje de sistema inicial
    chatHistory.RemoveRange(1, 2); 
}
```

### 4.8.4 Integración con Bot Framework State Management

En aplicaciones empresariales escalables (como bots desplegados en Azure Bot Service), el estado no puede residir únicamente en la memoria de la aplicación. Bot Framework proporciona un ecosistema robusto para persistir este historial.

El `ConversationState` y el `UserState` de Bot Framework permiten almacenar el `ChatHistory` en proveedores como **Azure Cosmos DB** o **Blob Storage**. Esto garantiza que, si el servicio se reinicia o el usuario cambia de dispositivo, el contexto del RAG se mantenga intacto.

```csharp
// Fragmento conceptual de integración en un Bot de Teams/Web
public override async Task OnMessageActivityAsync(ITurnContext<IMessageActivity> turnContext, CancellationToken cancellationToken)
{
    var conversationStateAccessors = _conversationState.CreateProperty<ChatHistory>("History");
    var history = await conversationStateAccessors.GetAsync(turnContext, () => new ChatHistory());

    // 1. Agregar mensaje actual al historial
    history.AddUserMessage(turnContext.Activity.Text);

    // 2. Lógica RAG (Recuperación + Generación usando el historial)
    var response = await _ragService.GenerateResponseAsync(history);

    // 3. Actualizar historial y persistir
    history.AddAssistantMessage(response);
    await _conversationState.SaveChangesAsync(turnContext);
    
    await turnContext.SendActivityAsync(MessageFactory.Text(response), cancellationToken);
}
```

### 4.8.5 Impacto en la Recuperación (Retrieval)

Es fundamental entender que el historial no solo ayuda a la generación, sino que es crítico para la **recuperación**. Si el usuario pregunta "Dime más", y no utilizamos el historial para reescribir esa consulta antes de ir a la base de datos vectorial, la búsqueda fallará por falta de términos clave.

En Semantic Kernel, esto se resuelve inyectando el objeto `ChatHistory` en un prompt de "reformulación de consulta" previo a la llamada del servicio de búsqueda (como Azure AI Search), asegurando que los fragmentos de PDF recuperados sean realmente relevantes para el hilo conductor de la charla.
